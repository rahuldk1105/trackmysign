How it works

Your original bytes are never rewritten.

Many PDF tools re-save the whole file when they add a signature, which silently breaks the auditor's or co-director's signature already on it. TrackMy Sign appends its signature after the last byte, the way the PDF standard intends for documents signed by more than one person.

board-resolution_signed.pdf/ByteRange [0 48,920 65,306 4,511]
Original file %PDF-1.7 header · 42 objects · xref · trailer · %%EOF bytes 0 – 48,213 · unchanged hashed
Signature dictionary /Type /Sig · /ByteRange · /M +707 B hashed
/Contents PKCS#7 signature from the token 16,386 B excluded
Stamp, xref, trailer widget · appearance · /Prev +4,511 B hashed
SHA-256 covers these bytes not hashed: holds the signature hashed
Typical editor
Whole file regenerated → earlier signature shows “document has been modified”.

  1. Open the PDF

    Drag it into the window. The app finds your token through the PKCS#11 driver that came with it.

  2. Place the signature

    Click anywhere on any page; drag to move, drag the corner to resize. The position is remembered.

  3. Enter the PIN

    The token signs a SHA-256 hash; the key never leaves it. The copy is saved as name_signed.pdf.

The app

One window. No setup wizard, no account.

Toolbar with page and zoom controls, the document in the middle, and everything about the signature on the right: signer, stamp text, position in millimetres. The status bar shows which token and driver are in use.

Signing

Standard PDF signatures from your USB token, for one document or a stack of them.

Signing in detail →

  • Tokens

    Every common Indian DSC token

    Drivers for the tokens Indian Certifying Authorities ship are found automatically, and certificates from all of them are listed together.

    • HyperPKI · ePass2003 · ProxKey · mToken
    • Trust Key · Watchdata · SafeNet · IDPrime · Bit4id
    • Per-signature-PIN keys supported

  • Batch

    Many PDFs, one PIN

    Select a stack of PDFs, place the box once and sign them all in one session. A file that fails never stops the rest.

    • One PIN entry for the whole batch
    • Box position shared across files
    • Signed copies never overwrite a file

  • Pages

    Every page, one signature

    Show the signature box on all pages or a range such as 1-3, 5. It is still one signature and one PIN entry.

    • All pages or ranges like 1-3, 5
    • One /ByteRange, one PIN
    • Same box position on each page

  • Forms

    Sign into existing boxes

    Bank and government PDFs often carry empty signature fields. Click one and the signature fills it, honouring its locks.

    • Empty fields highlighted and listed
    • FieldMDP locks recorded in the signature
    • Unsupported field formats refused, with a reason

  • Certify

    Lock the document

    Make the first signature a certification that says what may change afterwards.

    • No changes allowed
    • Form filling and signing
    • Also comments (DocMDP 1–3)

  • Long-term

    Valid after the DSC expires

    Optional trusted timestamp and embedded revocation data, so the signature can still be checked years later.

    • RFC 3161 timestamp
    • OCSP and CRL answers in /DSS (PAdES LTV)
    • Off by default: signing stays offline

Documents & files in detail →

    • Left of or above the text

    Presets for each kind of document

    Save the reason, location, box position, pages and design once, and pick them per document.

    • Reason, location, placement in mm
    • Signature image and design

    Page tools

Verification & records

Check what you receive, prove what you signed, and know when your DSC runs out.

Verification & records in detail →

  • Verify

    Check any signed PDF

    See who signed, whether each signature is valid, whether the chain reaches CCA India, and what changed after signing.

    • Integrity of the signed bytes
    • Chain to the CCA India 2022 root
    • Changes after each signature

  • Audit

    Verification report

    Export a PDF report of every signature in a document for auditors, or JSON from the command line.

    • A4 PDF with the file's SHA-256
    • Time of check in IST and UTC
    • JSON with a documented schema

  • Folders

    Verify a whole folder

    Check every signed PDF in a folder at once, filter the problems, and export one PDF report or a spreadsheet.

    • Subfolders optional
    • Filter: all, problems, unsigned
    • PDF report and CSV export

  • History

    Signing history

    A private, tamper-evident log of everything you sign, with search and CSV or PDF export. Can be turned off.

    • Hash-chained JSON Lines, one file per month
    • Search by file, signer, date, source
    • Never holds a PIN or document content

  • Certificate

    See and share your DSC

    Class, CA, validity, fingerprints and chain at a glance. Save the public certificate for a bank or portal that asks for it.

    • Class 1/2/3 and eKYC policies named
    • SHA-1 and SHA-256 fingerprints
    • Export .cer, .pem or .p7b

  • Reminders

    DSC expiry reminder

    Days left are always shown, with a reminder before your certificate expires, even when the token is not plugged in.

    • 30 days ahead by default
    • 15, 60 days or off
    • Expired certificates are refused

Specification

What it produces, exactly.

The signing engine is a small Rust library you can read in an afternoon. Every release is built by GitHub Actions from the public source.

Signature format
PKCS#7 / CMS detached adbe.pkcs7.detached, SHA-256, signingCertificateV2
Signature types
Approval, or certification with DocMDP levels 1–3; FieldMDP locks honoured
Long-term validity
Optional RFC 3161 timestamp and /DSS with OCSP and CRL data (PAdES LTV)
Encrypted PDFs
RC4 40/128-bit, AES-128, AES-256 (revisions 2–6)
Write method
Incremental update; original bytes never rewritten
Token access
PKCS#11 through the token's own driver; the private key never leaves the token
Verified in
Adobe Acrobat Reader — “Signature is valid”, trust via AATL
Tokens
Tested with Hypersecu HyperPKI HYP2003; drivers for ePass2003, ProxKey, mToken, Trust Key, Watchdata, SafeNet, Gemalto, Bit4id and OpenSC detected automatically

FAQ

Questions directors ask.

Is a signature made with TrackMy Sign legally valid?

The legal weight comes from your DSC, issued by a licensed Certifying Authority under the IT Act, 2000, not from the software that applies it. TrackMy Sign produces a standard PKCS#7 signature with your certificate, which Adobe Reader verifies like any other DSC signature.

Is my document uploaded anywhere?

No. The app has no server and your documents, certificates and PIN never leave your computer. You can sign with the network cable unplugged. It only goes online to check for updates (can be turned off) and, if you switch them on, for a trusted timestamp or revocation info. See the privacy statement.

Will it break signatures already on the PDF?

No. It writes an incremental update after the existing bytes instead of re-saving the file, which is what keeps earlier signatures valid.

Which tokens work?

Tested with Hypersecu HyperPKI HYP2003. The app also looks for the drivers of Feitian ePass2003, Watchdata ProxKey, mToken CryptoID, Trust Key, SafeNet eToken, Gemalto IDPrime and Bit4id, and lists certificates from every one it finds. If yours isn't detected, open an issue with the token's name and driver file.

Can I use it for MCA filings?

It signs PDFs: financial statements, resolutions, attachments. On the GST portal it can also sign without a separate signer utility (turn on Settings → GST portal signing). MCA21 V3 and the Income Tax portal use eMudhra's emBridge with licensed encryption, so keep using emBridge there.

Why does Windows warn me during install?

Only the direct installer warns: it isn't code-signed yet, so SmartScreen doesn't recognise the publisher (choose More info, then Run anyway). Install from the Microsoft Store instead and there is no warning, because Microsoft signs the Store version. Every release is built in public by GitHub Actions, and the macOS app is signed and notarized by Apple.
