# winget

Manifests for the Windows Package Manager community repository,
[microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs), so that
`winget install --id TrackMyTech.TrackMySign` installs the app.

- `manifest.py generate` writes the three manifests of a version (version,
  `en-US` default locale, installer; schema 1.12.0) to
  `manifests/t/TrackMyTech/TrackMySign/<version>/`, the layout of winget-pkgs.
  `manifest.py validate` checks them against the official JSON schemas in
  `schemas/` (copied from microsoft/winget-cli) and checks that the files agree
  with each other and with their folder.
- `python3 -m unittest discover -s packaging/winget` runs the tests (CI does,
  in the test job). Needs `pip install jsonschema pyyaml`.
- `manifests/` holds the manifests of v0.5.0, the version for the first
  submission. Later versions are generated by CI and not kept here.

The installer is Tauri's NSIS installer, per user (`installMode: currentUser`):
no admin rights, installs to `%LocalAppData%\TrackMySign`, `/S` silent, `/P`
progress only. It writes the uninstall entry
`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\TrackMySign` with
Publisher `TrackMy Tech Private Limited` (`bundle.publisher` in
`tauri.conf.json`) and DisplayName `TrackMy Sign` (set by
`apps/desktop/src-tauri/windows/hooks.nsh`), which winget uses to find the
installed version (`ProductCode: TrackMySign`, `AppsAndFeaturesEntries`). The
key name stays `TrackMySign` (productName). Up to v0.5.0 the installer wrote
DisplayName `TrackMySign` and Publisher `DK Rahul`; `EARLIER` in
`manifest.py` keeps the v0.5.0 manifests describing that installer. The
installer is not code-signed; winget-pkgs accepts that, but it is scanned
during validation.

## First submission (once)

winget-pkgs takes a new package only as a "New package" pull request, reviewed
by a moderator. `komac new` asks its questions interactively, so the
generated manifests are submitted with `komac submit` instead:

1. Fork <https://github.com/microsoft/winget-pkgs> to your account (*Fork*,
   default settings). komac does not create the fork.
2. Create a classic personal access token with only the `public_repo` scope
   (GitHub → Settings → Developer settings → Personal access tokens →
   Tokens (classic)). Fine-grained tokens cannot open the pull request.
3. Install [komac](https://github.com/russellbanks/Komac) 2.16 or newer
   (`winget install komac`, `cargo install --locked komac`, or the release
   binary).
4. Optional, on Windows: check the manifests with winget itself.

   ```
   winget validate --manifest packaging\winget\manifests\t\TrackMyTech\TrackMySign\0.5.0
   winget settings --enable LocalManifestFiles   (admin terminal, once)
   winget install --manifest packaging\winget\manifests\t\TrackMyTech\TrackMySign\0.5.0
   ```

5. Submit:

   ```
   komac submit packaging/winget/manifests/t/TrackMyTech/TrackMySign/0.5.0 --yes --token <token>
   ```

   This opens "New package: TrackMyTech.TrackMySign version 0.5.0" from your
   fork.
6. On the pull request, sign the Microsoft CLA when the bot asks (reply as it
   says). Automated validation runs (labels such as
   `Azure-Pipeline-Passed`, `Validation-Completed`); answer any moderator
   questions on the pull request. After it is merged, `winget install` works
   within a few hours.
7. Add the same token as the repository secret `WINGET_TOKEN`
   (Settings → Secrets and variables → Actions).

The v0.5.0 manifests hold the SHA-256 of the v0.5.0 release asset. If that
asset is ever uploaded again, regenerate them:
`python3 packaging/winget/manifest.py generate --version 0.5.0 --installer TrackMySign-Setup-windows-x64.exe --release-date 2026-10-24`.

## Later releases

For each real release (a `v*` tag, or `release_tag` in a manual run; never
`test-build`) the `winget` job in `.github/workflows/ci.yml` generates and
validates the manifests for that version and keeps them as the
`winget-manifests` workflow artifact. If `WINGET_TOKEN` is set and the package
is already in winget-pkgs, it submits them with

```
komac submit <manifests>/t/TrackMyTech/TrackMySign/<version> --yes
```

which opens the update pull request. (Not `komac update`: it copies the
previous version's manifests, including the Apps & Features publisher and
name of v0.5.0.) Without the secret, or before the first version is merged,
nothing is submitted.
